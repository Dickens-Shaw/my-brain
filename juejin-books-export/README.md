# 掘金小册整理

把攒在本机的掘金小册收成统一格式的本地 Markdown：一册一个目录，章节命名统一成
`序号-标题.md`，每章带 YAML frontmatter，每册配一份 `00-目录.md`。
零第三方依赖，只用 Python 标准库。

和旁边三条管线不一样，这条**不联网**。小册不是接口能拉的东西，`input/` 里放的是
你自己攒下来的下载产物，这条管线只做本地规整。唯一会走网络的是可选的远程配图下载。

## 快速开始

```bash
cd juejin-books-export
bash run.sh
```

两步各自也能单独跑：

```bash
python3 scripts/scan_books.py      # 盘点册和章节，出清单
python3 scripts/build_books.py     # 按清单转成 Markdown
```

只想先看清单不转换，或者只转某一册：

```bash
BUILD=0 bash run.sh                # 只盘点
BOOK=Babel bash run.sh             # 只转书名含 Babel 的
IMAGES=1 bash run.sh               # 顺手把远程配图也存到本地
```

## 输入长什么样

`input/` 下一本一个文件夹，文件夹名就是册名：

```
input/
├── TypeScript 全面进阶指南/          # Markdown 册
│   ├── 1.开篇：用正确的方式学习 TypeScript.md
│   └── 2.夯实基础：那些貌似"熟悉"的类型.md
├── WebGL 入门与实践/                 # HTML 册，配图是同目录的本地文件
│   ├── 1初级入门 --- 认识 WebGL.html
│   └── p1-jj.byteimg.comtos-cn-...awebp
├── 深入浅出Vite/                     # PDF 册，只登记不转换
│   └── 1 开篇：让 Vite 助力你的前端工程化之路.pdf
└── pdf/                             # 不成册的散本 PDF
    └── 前端面试小册.pdf
```

`input/` 和 `output/` 都在 `.gitignore` 里。小册是付费内容，只留在本机，别提交也别分发。

## 产出结构

```
output/
├── books.json                    # 册和章节清单，build_books.py 的输入
├── books.md                      # 人读的总目录，含形态统计和缺失登记
└── books/
    ├── TypeScript 全面进阶指南/
    │   ├── 00-目录.md
    │   ├── 01-开篇：用正确的方式学习 TypeScript.md
    │   └── 33-类型编程的未来.md
    ├── WebGL 入门与实践/
    │   ├── 00-目录.md
    │   ├── 01-初级入门 --- 认识 WebGL.md
    │   └── assets/               # 从册目录搬过来的配图，后缀按文件头修正
    └── 未转换清单.md              # PDF 册、空文件、转换失败的都记在这
```

每章的 frontmatter：

```yaml
---
title: "[命令行动画龟兔赛跑] Node 的语言基础 - JS（ES5/6/7/8）"
site: "juejin.cn"
book: "10+ 代码案例掌握 NodeJS 核心基础知识"
chapter: 2
chapter_total: 14
source_format: "markdown"
order_source: "filename"
title_source: "文件内标题"
source_file: "10+ 代码案例掌握 NodeJS 核心基础知识/2案例一： [龟兔赛跑] Node 的语言基础 - JS（ES5[6[7[8）.md"
converted_at: "2026-07-29 13:41:02"
---
```

`source_file` 一直指回 `input/` 里的原始文件，产出有疑问随时能对着看原件。
`order_source` 和 `title_source` 记的是序号和标题从哪来的，下面两节解释。

## 三种形态，三种处理

| 形态 | 册数 | 章节 | 处理方式 |
| --- | --- | --- | --- |
| Markdown | 30 | 645 | 原文照搬，补 frontmatter 和标题，修掉反斜杠图片路径 |
| HTML | 5 | 104 | 转成 Markdown，同目录配图搬进 `assets/` |
| PDF | 4 | 80 | 标准库解析不了，只登记不转换，原始文件不动 |

PDF 那 4 组（`深入浅出Vite`、`React 实战：设计模式和最佳实践`、
`从 0 到 1 落地前端工程化`，加 `pdf/` 里 7 个散本）想转文字就得引第三方库，
为了守住零依赖这条线，这里只在 `未转换清单.md` 里登记位置。

## 序号和标题是怎么还原的

这批文件的命名基本没有规律，同一件事有五六种写法：

```
1.开篇：用正确的方式学习 TypeScript.md      # 数字 + 点
01.md                                     # 只有编号，标题不在文件名里
10、React 单元测试.pdf                      # 数字 + 顿号
9 资源加速：静态资源加载过慢？.pdf            # 数字 + 空格
21中级进阶 --- 坐标系变换.html               # 数字直接顶着标题
10响应式原理：xxx学习时长20分14秒.html        # 尾巴还挂着播放时长
职业规划 1：通过职业价值论理解程序员的价值.md   # 压根没有序号
```

`scan_books.py` 把这些收敛成统一的序号加标题。`order_source` 记下序号的来路：

- `filename` —— 文件名里有序号，直接用
- `filename-partial` —— 一册里只有部分文件带序号，无序号的排在后面
- `sequence` —— 整册都没有序号，只能按文件名排。**这几册的章节顺序不等于真实阅读顺序**，
  册内 `00-目录.md` 会写明这一点，读的时候以标题为准

`title_source` 记标题的来路，优先级从高到低：

- `文件内标题` —— 正文首行那个 `#` 标题。优先用它是因为文件名会丢字符：
  `JS（ES5/6/7/8）` 存成文件只能写作 `JS（ES5[6[7[8）`，冒号问号也一样。首行标题和文件名
  标题说的是同一件事（归一化后相似度 ≥ 0.75）时就采信文件里那份，并把这行从正文里摘掉，
  免得和脚本补的标题重复
- `目录.txt` —— 文件名只有编号（`01.md`）且正文里也没有标题时，从册内的 `目录.txt`
  按编号取回来。`前端调试通关秘籍` 和 `现代web布局` 靠这个救回了 75 章的标题
- `文件名` —— 从文件名里拆出来的
- `缺失` —— 三处都没有，退化成「第 N 章」

## 图片

册内的本地配图一律搬进 `<册>/assets/`，目录层级保留。这里有两个坑：

**后缀不可信。** 小册里的图片后缀有 `.awebp`、`.image`，还有干脆没后缀的（`img/2/1`），
直接引用在 Obsidian 里渲染不出来。脚本按文件头判断真实格式重命名，同时改写正文引用。
实测 1251 张里有 1069 张 webp、153 张 png、15 张 jpg、12 张 gif、2 张 svg。

**引用和文件名差一个字符。** 存网页的工具把图床 URL 压平成文件名时，正文引用留下了
`?` 结尾的查询串，磁盘上的文件名却没有。脚本会按几种写法轮着找，所以 `NestJS 项目实战`
和 `可视化入门` 那 239 处引用不会变成死链。

HTML 册的配图文件名是整条压平的 URL，截断到 60 字符后前缀大量重复，脚本撞名就补序号，
不会互相覆盖。

正文里的远程 `byteimg.com` 地址默认保留原样——这些地址没有防盗链，能正常渲染。
想彻底离线就加 `--download-images`，会存到 `<册>/assets/remote/`。

## 常用参数

### scripts/scan_books.py

| 参数 | 说明 |
| --- | --- |
| `--input` | 小册原始文件目录，默认 `input` |
| `--output` | 输出目录，默认 `output` |

### scripts/build_books.py

| 参数 | 说明 |
| --- | --- |
| `--input` | 小册原始文件目录，默认 `input` |
| `--index` | 清单路径，默认 `output/books.json` |
| `--output` | 输出目录，默认 `output/books` |
| `--book Babel` | 只转书名包含这个词的册 |
| `--download-images` | 远程配图也存到本地 |
| `--interval 0.3` | 下载远程配图的请求间隔秒数 |

`run.sh` 认这几个环境变量：`INPUT_DIR`、`OUTPUT_DIR`、`BOOK`、`IMAGES=1`（下载远程配图）、
`BUILD=0`（只盘点不转换）。写在仓库根目录 `.env` 里等效。

转换是纯本地操作，全量 5 秒跑完，所以没做断点续传——重跑一遍比维护进度文件省事。

## 实现说明

- HTML 转 Markdown 用的是 `scripts/html_to_markdown.py`，从
  `juejin-articles-export/scripts/fetch_articles.py` 移植过来的。仓库里每条管线都自带一份
  转换器（`chrome-bookmarks-export` 也是），刻意不抽公共库：代价是重复，好处是任何一条
  管线可以单独拷走就能跑。
- 和文章版的唯一区别是图片地址的处理。文章版处理线上页面，相对地址一律补成绝对 URL；
  这里的 HTML 存在本机，相对地址就是同目录的配图，得原样留着交给 `build_books.py` 搬运。
- 保存网页时「复制代码」按钮的文字被卷进了代码块首行（`js复制代码import ...`），
  转换后统一清掉，322 处。
- Markdown 册的正文里如果还有 `h1`，统一降到 `h2`，保证一个文件只有开头那个顶层标题。
  代码块内的 `#` 不动。
- `Vue 项目构建与开发入门` 那册每章都存了两份（编号版和无编号版，内容一字不差），
  按内容哈希去重后留带序号的那份，34 个文件收成 19 章。
- 章节顺序、标题、去重这些判断都写进 `books.json` 和册内 `00-目录.md`，没有猜测性修复：
  推不出来的就如实标注，不假装知道。

## 缺的部分

9 章的源文件是 0 字节，下载时就没落全，恢复不了，都登记在 `未转换清单.md`：

- `Babel 插件通关秘籍` 第 17~23 章（7 章实战案例）
- `React 进阶实践指南` 第 38 章
- `基于 JavaScript 开发灵活的数据应用` 第 21 章

`React 进阶实践指南` 那 40 章的标题也恢复不了：文件名只有编号（`01.md`），册内没有
`目录.txt`，正文首个标题是节标题（「一 前言」这种），拿来当章标题会错，所以退化成
「第 N 章」，`title_source` 记成 `缺失`。章节顺序是准的，内容也完整。

另外有 2 章的代码围栏本来就不配平（`3案例二：[视频时长统计] Node 的模块机制`、
`12.可视化编辑区实现`），是作者原稿写坏了，源文件和产出的围栏数一致，脚本如实转换不做修补。
